All notable changes to the `docker` extension. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/); releases are tagged `docker@<version>`.

## [Unreleased]

## [1.0.0] - 2026-11-14

### Added
- **Containers** of the machine grouped by Compose project, kept live with `docker events`: state and health, image, published ports as links, ports exposed but not published, uptime, CPU and memory (`docker stats`, optional). Start, stop, restart, remove (with its anonymous volumes), live logs in the output drawer, details with the environment (secret-looking values blurred until clicked). Project actions: up, restart, stop, down (orphans and volumes only when asked, volumes with a second confirmation), logs of all the services.
- **Compose files of the Kelbo projects** (`compose.yaml`, `docker-compose.yml`, overrides and variants, in the project folder or one folder below) in the sidebar with how many of their containers run; the running Compose projects outside Kelbo are listed too. Projects with a compose file or a Dockerfile get the `docker` trait.
- **Graph of the services**: one column per dependency level (dependencies on the left), named volumes, published and internal ports, networks as coloured stripes, `depends_on` edges by condition (started, healthy, completed), the state of each service's containers and its problems. Right click on a service: up, restart, stop, logs of that service, database connection, tunnel, remove.
- **Visual editor**: click a service to edit name (renaming updates `depends_on`, `links`, `network_mode`, `volumes_from` of the others), image, build folder and Dockerfile, command, ports, environment, volumes, dependencies with their condition, recommended healthcheck, restart policy, profiles and networks. With nothing selected: **add a service** from ready templates (PostgreSQL, MySQL, MariaDB, SQL Server, MongoDB, Redis, RabbitMQ, Mailpit, Adminer, Nginx, Node app, empty) with a pinned image tag, variables with defaults, a **free host port bound to 127.0.0.1**, a named volume and a healthcheck; Compose project name, named volumes and networks, and where each variable comes from (`.env`, environment, default, missing). Changes are applied to the YAML document, so comments and the formatting of everything else stay as they were.
- **YAML editor** with analysis while typing and the YAML errors with their line; **Validate** runs `docker compose config` on the current text (saved or not); **Save** refuses to overwrite a file changed on disk in the meantime (and asks); new compose files are created in a project at the first save.
- **Analysis** of the file as Compose sees it (variables from the `.env` next to it and the environment, the `override` file merged in): ports already used on the machine (with the process) or by another container, ports published twice, unknown dependencies and cycles, `service_healthy` towards a service without healthcheck, dependencies on a database without waiting for it to be ready, undeclared or unused volumes and networks, missing variables, `env_file`s, bind paths, build folders and Dockerfiles, images without a tag or `latest`, secrets written in clear, database ports open on all interfaces, the Docker socket mounted, privileged services, the obsolete `version` key. Fixes in one click where it is safe (remove `version`, declare volumes and networks, add the healthcheck and wait for healthy, bind to 127.0.0.1, move to a free port), or all of them at once.
- **Commands** `up` (with build, pull, recreate, remove orphans), `down`, `stop`, `start`, `restart`, `pull`, `build` of the whole file or of a service, run as jobs with the output streamed in the output drawer.
- **Tunnel transport** *Docker container* for the Tunnels section (Kelbo 2.34 `tunnel-transport`): a tunnel to any port of a running container, also when it is not published, through a small `alpine/socat` container on the same network that publishes `127.0.0.1:<local port>` (it works with Docker Desktop on macOS and Windows too) and is removed when the tunnel stops.
- **Database connection** from a database container (PostgreSQL, MySQL, MariaDB, SQL Server, Oracle): the Database section opens the form of a new connection already filled in with host, published port, user, password and database read from the container's environment (Kelbo 2.36); when the port is not published, the Tunnels form opens first.
- MCP tools `docker_containers`, `docker_compose_projects`, `docker_analyze`, `docker_logs` (read-only; environment values are never returned).
